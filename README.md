# Генератор описаний товаров

Программа готовит черновик карточки для B2B-магазина: заголовок, описание,
характеристики, поисковые запросы и подсказку менеджеру. На входе — JSON-файл
с данными товара. Текст обрабатывает языковая модель через API; по умолчанию — Groq.

## 1. Подготовка

Установите [Python](https://www.python.org/downloads/) версии 3.11 или новее
и откройте терминал в папке проекта. Внешние библиотеки устанавливать не нужно.

```powershell
python --version
```

Если в Windows команда не найдена, используйте `py` вместо `python`.

## 2. Получение ключа

Зарегистрируйтесь в [Groq Console](https://console.groq.com/keys).
В разделе API Keys создайте ключ и скопируйте его. Ключ нужен программе
для доступа к модели; не добавляйте его в файлы проекта.

В PowerShell выполните:

```powershell
$secret = Read-Host 'Вставьте ключ Groq' -AsSecureString
$env:GROQ_API_KEY = [System.Net.NetworkCredential]::new('', $secret).Password
Remove-Variable secret
```

При вводе символы ключа скрыты. Настройка действует только в этом терминале.
Если ключ уже сохранен в переменных пользователя Windows, вместо ввода выполните:

```powershell
$env:GROQ_API_KEY = [Environment]::GetEnvironmentVariable('GROQ_API_KEY', 'User')
```

## 3. Запуск

В проекте есть данные двух товаров. Чтобы получить карточки:

```powershell
python -m product_writer examples/products.json --output output/result.json
```

Для результата с заголовками и списками, удобного для чтения и копирования:

```powershell
python -m product_writer examples/products.json --format markdown --output output/result.md
```

Файл появится в папке `output`. Без `--output` результат выводится в терминал.
Это два самостоятельных запуска: каждый обращается к модели и расходует квоту.
Готовые примеры можно посмотреть без ключа:
[карточки](examples/result.groq.md), [данные результата](examples/result.groq.json).

## 4. Другая модель

Чтобы сменить модель внутри Groq, выберите ее имя в
[списке моделей](https://console.groq.com/docs/models) и задайте настройку:

```powershell
$env:GROQ_MODEL = 'имя-модели-из-списка'
```

По умолчанию используется `openai/gpt-oss-120b`. Нужна текстовая модель,
которая умеет возвращать JSON и доступна вашему аккаунту.

Другой сервис можно подключить, если он поддерживает тот же формат запросов
Chat Completions. Возьмите адрес API, название модели и ключ у его поставщика:

```powershell
$env:LLM_BASE_URL = 'https://адрес-сервиса/v1'
$env:LLM_MODEL = 'название-модели'
$secret = Read-Host 'Ключ выбранного сервиса' -AsSecureString
$env:LLM_API_KEY = [System.Net.NetworkCredential]::new('', $secret).Password
Remove-Variable secret
python -m product_writer examples/products.json --output output/result.json
```

Адрес указывается без `/chat/completions`: программа добавит эту часть сама.
Сервис должен принимать `messages`, `temperature`, `max_tokens` и
`response_format: {"type":"json_object"}`. Для других форматов потребуется
изменить `llm.py`; совместимость со всеми моделями не гарантируется.
Ключ Groq не отправляется на адрес другого поставщика автоматически.
Для локальной модели разрешен HTTP на `localhost` или `127.0.0.1`.
Если локальный сервер не проверяет ключ, задайте `LLM_API_KEY=local`.

Настройки `LLM_*` имеют приоритет. Чтобы вернуться к Groq, удалите их
из окружения текущего терминала:

```powershell
Remove-Item Env:LLM_BASE_URL, Env:LLM_MODEL, Env:LLM_API_KEY -ErrorAction SilentlyContinue
```

`.env.example` — список настроек. Копирование его в `.env` само по себе
ничего не меняет: программа читает переменные окружения.

## 5. Свои товары

Скопируйте `examples/products.json` и замените сведения. Файл должен содержать
один объект товара или список из 1-20 объектов. Кодировка — UTF-8, размер — до 1 MB.

| Поле | Что указать |
|---|---|
| `name` | Название модели; обязательное поле |
| `manufacturer` | Производитель |
| `specs` | Характеристики со значениями и единицами, например `"Питание": "24 В"` |
| `description` | Описание назначения и функций из документации |
| `required_specs` | Какие характеристики должны быть заполнены |
| `product_type` | Тип прибора, например «GSM-модем» |
| `audience` | Кому подходит прибор согласно его назначению |
| `tasks` | До 5 задач, которые прибор решает согласно исходным сведениям |
| `source_url` | Ссылка на источник |
| `source_notes` | Замечания, которые нужно проверить перед публикацией |

Неизвестное значение характеристики можно указать как `null`.
В карточке оно будет отмечено словами «данных нет».
Если `required_specs` не задан, программа сообщает, что полнота не проверена.
Если сведений не хватает для описания, она возвращает `needs_clarification`
и объясняет, что добавить. Неверный товар не мешает обработке остальных.

## Как устроена программа

| Где | Что хранится |
|---|---|
| `product_writer/core.py` | Проверка данных, сборка карточки и оформление Markdown |
| `product_writer/llm.py` | Настройки API, запрос к модели и промпт — инструкция для нее |
| `product_writer/cli.py` | Команды запуска, чтение и сохранение файлов |
| `examples/` | Два исходных товара и реальные результаты Groq |
| `tests/test_writer.py` | Автоматические проверки |
| `.env.example` | Названия настроек без ключей |

Модель выбирает исходные фрагменты и возвращает план. Программа собирает текст
и проверяет заголовок до 70 символов, описание 800-1200 символов и 3-5 запросов.
Характеристики копируются из входа. Для менеджера отдельно указываются
аудитория и задачи. Это ограничивает выдумывание параметров, но дает меньше
свободы формулировок, чем обычное написание текста моделью.

Товары выбраны из [фида СОЮЗ-ПРИБОР](https://www.souz-pribor.ru/yml/any/feed.xml).
Описание дополнено по страницам товаров; ссылки и спорные сведения сохранены
во входном файле. Аудитория и задачи подготовлены по исходному назначению.

## Проверка и ошибки

```powershell
python -m unittest discover -s tests -v
```

Тесты работают без ключа и без сети. Они проверяют данные, ограничения текста,
обработку ошибок API и продолжение работы при ошибке отдельного товара.

| Ошибка | Что проверить |
|---|---|
| Ключ не задан / HTTP 401 | Ключ установлен в том же терминале, откуда запущена команда |
| HTTP 403/404 | Доступ к модели, ее имя и адрес API |
| HTTP 400 | Поддерживает ли выбранная модель параметры запроса |
| HTTP 429 | Лимиты аккаунта; повторить позже |
| Недостаточно данных | Добавить подтвержденные сведения о назначении и функциях |

Сетевые ошибки и HTTP 429/5xx повторяются до 3 раз. Некорректный ответ модели —
до 3 попыток исправления. При сочетании ошибок возможны до 9 обращений на товар;
ожидание ответа одного запроса ограничено 40 секундами.
Коды завершения: `0` — успех, `1` — ошибки отдельных товаров,
`2` — ошибка файла, настроек или структуры всего JSON.

## Ограничения

Карточки — черновики. Программа не проверяет достоверность источника,
не разрешает противоречия между версиями прибора и не оценивает частотность
поисковых запросов. Короткого исходника может не хватить для 800 символов.
Повторы проверяются по словам, а не по полному смыслу. Длинное название
в базовом заголовке обрезается до 70 символов.

Дальнейшие улучшения: проверка противоречий в исходных данных, извлечение
аудитории и задач из документации, улучшение связности текста и простая веб-форма.
